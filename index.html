Dokumentasi Build Kernel Rosemary

Redmi Note 10S / POCO M5s (Rosemary) — Kernel 4.14 Vendor-Based

Kernel 4.14 KernelSU Next Manual Hook Proton Clang 13 Fedora 44

iPendahuluan

Dokumentasi ini menjelaskan cara build kernel untuk Redmi Note 10S / POCO M5s (Rosemary) dari source code, dengan dua opsi:

  • Dengan KernelSU Next — pakai manual hook (tanpa KPROBES)
  • Tanpa KernelSU — kernel bersih (stock-like)
⚠️ Risiko Flash kernel custom bisa menyebabkan bootloop dan, kalau salah langkah, kehilangan data. Siapkan backup boot.img (lihat bagian 7) dan lakukan dengan risiko sendiri.

0Persiapan Awal

0.1 Prasyarat

  • Bootloader perangkat sudah unlocked
  • Custom recovery (TWRP/OrangeFox), karena ZIP AnyKernel di-flash lewat recovery
  • adb dan fastboot di PC: sudo dnf install -y android-tools
  • Disk kosong minimal 20 GB dan RAM yang cukup (kalau build berakhir Killed, kurangi -j)

0.2 Clone Source Kernel

cd ~/android
git clone https://github.com/gabutgadungan/android_kernel_xiaomi_rosemary
cd android_kernel_xiaomi_rosemary
git checkout zenith-ksu

0.3 Cek Toolchain

ls ~/toolchain/proton-clang/bin/clang
~/toolchain/proton-clang/bin/clang --version

Pastikan Proton Clang 13 tersedia beserta llvm-ar, llvm-nm, ld.lld, dan cross-compiler GCC (aarch64-linux-gnu, arm-linux-gnueabi).

0.4 Install Dependencies (Fedora)

sudo dnf install -y git make gcc gcc-c++ flex bison \
    openssl-devel elfutils-libelf-devel bc perl python3 \
    zip unzip curl wget ncurses-devel libxml2-devel dwarves

0.5 Siapkan AnyKernel3

Lewati langkah ini kalau folder ~/android/AnyKernel3-KSU sudah ada dan terkonfigurasi.

cd ~/android
git clone https://github.com/osm0sis/AnyKernel3 AnyKernel3-KSU

Lalu edit anykernel.sh: isi kernel.string, atur device.name1=rosemary (sesuaikan dengan codename perangkatmu), dan cek block serta is_slot_device sesuai partisi boot perangkat (nilai auto biasanya cukup).

1Cleanup KernelSU Lama

Jika sebelumnya sudah pernah patch KSU, bersihkan dulu.

1.1 Hapus Sisa Patch dari Makefile & Kconfig

cd ~/android/android_kernel_xiaomi_rosemary
curl -LSs "https://raw.githubusercontent.com/tiann/KernelSU/main/kernel/setup.sh" | bash -s -- --cleanup

Kalau script di atas gagal, atau patch lama berasal dari KernelSU-Next, bersihkan manual:

sed -i '/kernelsu/d' drivers/Makefile
sed -i '/drivers\/kernelsu\/Kconfig/d' drivers/Kconfig

1.2 Hapus Folder & Symlink Sisa

rm -rf drivers/kernelsu
rm -rf KernelSU KernelSU-Next
rm -f fs/*.bak kernel/*.bak

1.3 Verifikasi Bersih

grep -ri kernelsu drivers/Makefile drivers/Kconfig
ls -la drivers/ | grep kernelsu
✅ Berhasil Kedua perintah harus tidak menghasilkan output.
ℹ️ Hook di 5 file tidak ikut terhapus Cleanup hanya membersihkan Makefile, Kconfig, dan folder. Blok #ifdef CONFIG_KSU yang pernah kamu tambahkan di fs/ dan kernel/reboot.c tetap ada. Cek dengan git diff --stat dan jangan patch dua kali (lihat bagian 3.6).

2Setup KernelSU Next

2.1 Setup KernelSU Next (Legacy)

curl -LSs "https://raw.githubusercontent.com/KernelSU-Next/KernelSU-Next/next/kernel/setup.sh" | bash -s legacy

Output yang diharapkan:

  • Repository cloned
  • Checked out legacy
  • Symlink created
  • Modified Makefile
  • Modified Kconfig

Catat versi yang terpasang supaya build bisa direproduksi:

git -C KernelSU-Next log -1 --oneline
⚠️ Script dari internet curl ... | bash menjalankan script dari branch yang bisa berubah kapan saja. Untuk lebih aman, unduh dulu, baca isinya, baru jalankan: 
curl -LSso /tmp/ksun-setup.sh "https://raw.githubusercontent.com/KernelSU-Next/KernelSU-Next/next/kernel/setup.sh"
less /tmp/ksun-setup.sh
bash /tmp/ksun-setup.sh legacy

2.2 Perbaiki Symlink Jika Perlu

rm -rf drivers/kernelsu
ln -sf "$(realpath --relative-to="$(pwd)/drivers" "$(pwd)/KernelSU-Next/kernel")" drivers/kernelsu
ls -la drivers/ | grep kernelsu

Output harus lrwxrwxrwx ... kernelsu -> ../KernelSU-Next/kernel.

2.3 Verifikasi Kconfig & Makefile

grep -n "kernelsu" drivers/Kconfig drivers/Makefile

Harus muncul:

  • source "drivers/kernelsu/Kconfig" di drivers/Kconfig
  • obj-$(CONFIG_KSU) += kernelsu/ di drivers/Makefile

Jika Kconfig belum dimodifikasi:

sed -i '/^endmenu/i source "drivers/kernelsu/Kconfig"' drivers/Kconfig

3Patch Manual Hook (5 File)

⚠️ KPROBES Bermasalah di Kernel 4.14 MTK Gunakan Manual Hook sebagai gantinya.
ℹ️ Sesuaikan dengan versi Daftar hook di bawah mengikuti KernelSU-Next branch legacy pada commit yang kamu catat di langkah 2. Versi lain bisa punya signature berbeda atau butuh hook tambahan (misalnya drivers/input/input.c untuk safe mode). Kalau ragu, cocokkan dengan dokumentasi manual hook resmi.

3.1 fs/exec.c

Deklarasi extern di atas do_execve:

#ifdef CONFIG_KSU
__attribute__((hot))
extern int ksu_handle_execveat(int *fd, struct filename **filename_ptr,
				void *argv, void *envp, int *flags);
#endif

Hook di do_execve:

int do_execve(struct filename *filename,
	const char __user *const __user *__argv,
	const char __user *const __user *__envp)
{
	struct user_arg_ptr argv = { .ptr.native = __argv };
	struct user_arg_ptr envp = { .ptr.native = __envp };
#ifdef CONFIG_KSU
	ksu_handle_execveat((int *)AT_FDCWD, &filename, &argv, &envp, 0);
#endif
	return do_execveat_common(AT_FDCWD, filename, argv, envp, 0);
}

Hook juga di compat_do_execve (untuk 32-bit support):

#ifdef CONFIG_KSU // 32-bit ksud and 32-on-64 support
	ksu_handle_execveat((int *)AT_FDCWD, &filename, &argv, &envp, 0);
#endif

3.2 fs/open.c

Deklarasi extern di atas faccessat:

#ifdef CONFIG_KSU
__attribute__((hot))
extern int ksu_handle_faccessat(int *dfd, const char __user **filename_user,
				int *mode, int *flags);
#endif

Hook di dalam SYSCALL_DEFINE3(faccessat, ...), setelah deklarasi variabel:

#ifdef CONFIG_KSU
	ksu_handle_faccessat(&dfd, &filename, &mode, NULL);
#endif

3.3 fs/read_write.c

Deklarasi extern di atas SYSCALL_DEFINE3(read, ...):

#ifdef CONFIG_KSU
extern bool ksu_vfs_read_hook __read_mostly;
extern __attribute__((cold)) int ksu_handle_sys_read(unsigned int fd);
#endif

Hook di dalam SYSCALL_DEFINE3(read, ...):

#ifdef CONFIG_KSU
	if (unlikely(ksu_vfs_read_hook))
		ksu_handle_sys_read(fd);
#endif
ℹ️ Catatan Fungsi ksu_handle_sys_read hanya butuh 1 argumen (fd), bukan 3 seperti versi patch lama.

3.4 fs/stat.c

Deklarasi extern di atas SYSCALL_DEFINE4(newfstatat, ...):

#ifdef CONFIG_KSU
__attribute__((hot))
extern int ksu_handle_stat(int *dfd, const char __user **filename_user,
				int *flags);
#endif

Hook di dalam SYSCALL_DEFINE4(newfstatat, ...):

SYSCALL_DEFINE4(newfstatat, int, dfd, const char __user *, filename,
		struct stat __user *, statbuf, int, flag)
{
	struct kstat stat;
	int error;

#ifdef CONFIG_KSU
	ksu_handle_stat(&dfd, &filename, &flag);
#endif

	error = vfs_fstatat(dfd, filename, &stat, flag);
	...
}
❌ Jangan Letakkan Hook di newfstat Variabel dfd, filename, flag tidak ada di sana.

3.5 kernel/reboot.c

Deklarasi extern di atas SYSCALL_DEFINE4(reboot, ...):

#ifdef CONFIG_KSU
extern int ksu_handle_sys_reboot(int magic1, int magic2, unsigned int cmd, void __user **arg);
#endif

Hook di dalam SYSCALL_DEFINE4(reboot, ...):

#ifdef CONFIG_KSU
	ksu_handle_sys_reboot(magic1, magic2, cmd, &arg);
#endif
⚠️ Perhatian Argumen terakhir pakai &arg (by reference), sesuai signature void __user **arg.

3.6 Verifikasi Semua Patch

grep -l "ksu" fs/exec.c fs/open.c fs/read_write.c fs/stat.c kernel/reboot.c 2>/dev/null

Harus muncul 5 file. Pastikan tiap file hanya berubah sekali (tidak ada patch ganda):

git diff --stat -- fs/exec.c fs/open.c fs/read_write.c fs/stat.c kernel/reboot.c

4Konfigurasi Defconfig

4.1 Bersihkan Duplikasi

sed -i '/CONFIG_KSU/d; /CONFIG_KPROBES/d; /CONFIG_KPROBE_EVENTS/d; /CONFIG_HAVE_KPROBES/d; /CONFIG_HAVE_KPROBE_EVENTS/d; /Pastikan KPROBES/d' arch/arm64/configs/rosemary_defconfig

4.2 Tambahkan Konfigurasi Manual Hook

cat >> arch/arm64/configs/rosemary_defconfig << 'EOF'

# KernelSU Next - Manual Hook (NO KPROBES)
CONFIG_KSU=y
CONFIG_KSU_MANUAL_HOOK=y
# CONFIG_KSU_WITH_KPROBES is not set
# CONFIG_KPROBES is not set
# CONFIG_KPROBE_EVENTS is not set
EOF

4.3 Verifikasi Defconfig

grep -i -E "ksu|kprobe" arch/arm64/configs/rosemary_defconfig

Harus muncul bersih tanpa duplikasi: tiap opsi hanya satu kali.

ℹ️ Soal CONFIG_HAVE_KPROBES Opsi HAVE_* di-select oleh arsitektur ARM64, jadi tidak bisa dimatikan lewat defconfig dan tetap =y di .config. Itu normal. Yang harus nonaktif hanya CONFIG_KPROBES dan CONFIG_KPROBE_EVENTS.
⚠️ Defconfig di repo berubah Langkah ini memodifikasi rosemary_defconfig, jadi git status akan kotor. Cek dengan git diff arch/arm64/configs/rosemary_defconfig.

5Build Kernel

5.1 Bersihkan Output Lama

cd ~/android/android_kernel_xiaomi_rosemary
rm -rf out out-ksun
touch .scmversion

5.2 Set Environment Toolchain

Set dulu sebelum generate .config, supaya konfigurasi dibuat dengan toolchain yang sama dengan build.

export PATH="$HOME/toolchain/proton-clang/bin:$PATH"
export LD_LIBRARY_PATH="$HOME/toolchain/proton-clang/lib:$LD_LIBRARY_PATH"
export ARCH=arm64
export SUBARCH=arm64
export CROSS_COMPILE="$HOME/toolchain/proton-clang/aarch64-linux-gnu/bin/aarch64-linux-gnu-"
export CROSS_COMPILE_ARM32="$HOME/toolchain/proton-clang/arm-linux-gnueabi/bin/arm-linux-gnueabi-"
export LLVM=1
export LLVM_IAS=1
ℹ️ Soal LLVM=1 dan LLVM_IAS=1 Kernel 4.14 upstream belum mengenal kedua flag ini (baru diperkenalkan di kernel 5.x), kecuali repo-mu sudah mem-backport-nya. Compiler yang benar-benar dipakai ditentukan oleh CC, HOSTCC, dan HOSTCXX di perintah make. Flag ini tidak berbahaya, tapi jangan diandalkan.

5.3 Generate .config

make O=out-ksun ARCH=arm64 CC=clang HOSTCC=clang HOSTCXX=clang++ rosemary_defconfig

Pastikan muncul:

#
# configuration written to .config
#

Verifikasi:

grep -i -E "ksu|kprobe" out-ksun/.config

Yang diharapkan: CONFIG_KSU=y, CONFIG_KSU_MANUAL_HOOK=y, # CONFIG_KPROBES is not set, dan # CONFIG_KPROBE_EVENTS is not set. CONFIG_HAVE_KPROBES=y itu normal.

5.4 Kompilasi Kernel

make O=out-ksun -j$(nproc) \
    ARCH=arm64 \
    CC=clang \
    HOSTCC=clang \
    HOSTCXX=clang++ \
    2>&1 | tee build_ksun.log

Perkiraan waktu: 15-40 menit tergantung CPU.

5.5 Pantau Progress

# Ikuti log secara live (jalankan di terminal kedua)
tail -f build_ksun.log

# Cari error
grep -n -E "error:|\*\*\*" build_ksun.log | head

5.6 Output Kernel

Jika berhasil:

out-ksun/arch/arm64/boot/Image.gz
out-ksun/arch/arm64/boot/Image.gz-dtb

5.7 Verifikasi KernelSU Ter-compile

# Cek objek KSU
find out-ksun -name "*.o" -path "*kernelsu*" | head -20

# Cek symbol KSU di vmlinux
nm out-ksun/vmlinux 2>/dev/null | grep -i ksu | head -20

# Cek string KSU di Image
strings out-ksun/arch/arm64/boot/Image | grep -i -E "kernelsu|ksu_" | head -10

6Packing AnyKernel

6.1 Copy Kernel ke Folder AnyKernel

cp out-ksun/arch/arm64/boot/Image.gz-dtb ~/android/AnyKernel3-KSU/

6.2 Pack jadi ZIP

cd ~/android/AnyKernel3-KSU
DATE=$(date +%Y%m%d)
zip -r9 "Zenith-Rosemary-ksun-${DATE}.zip" * -x "*.zip"

-x "*.zip" mencegah ZIP hasil build sebelumnya ikut terkemas ke dalam ZIP baru. Image.gz-dtb lama otomatis tertimpa saat cp.

6.3 Verifikasi ZIP

ls -la ~/android/AnyKernel3-KSU/Zenith-Rosemary-ksun-*.zip
unzip -l "$(ls -t ~/android/AnyKernel3-KSU/Zenith-Rosemary-ksun-*.zip | head -1)"

Hasil: Zenith-Rosemary-ksun-YYYYMMDD.zip. Di dalamnya harus ada satu Image.gz-dtb dan tidak boleh ada file .zip lain.

7Flash ke Perangkat

⚠️ Backup Dulu! Simpan boot.img yang sekarang bisa boot dan data penting sebelum flash. Ini jalan keluar kalau terjadi bootloop.

7.1 Backup boot.img

Cek nama partisi boot dulu (boot, atau boot_a/boot_b), lalu backup. Cara ini butuh root; kalau belum ada root, ekstrak boot.img dari firmware/ROM yang sedang dipakai.

adb shell su -c "ls /dev/block/by-name | grep boot"
adb shell su -c "dd if=/dev/block/by-name/boot of=/sdcard/boot_backup.img"
adb pull /sdcard/boot_backup.img ~/android/

7.2 Transfer ZIP ke HP

adb push ~/android/AnyKernel3-KSU/Zenith-Rosemary-ksun-*.zip /sdcard/

7.3 Boot ke Recovery

Matikan HP, lalu tekan Volume Up + Power bersamaan.

7.4 Bersihkan Sisa Root Lama (Opsional)

⚠️ Peringatan Ini menghapus semua modul dan konfigurasi root lama. Lewati kalau kamu tidak berpindah dari solusi root lain. Di recovery, /data yang terenkripsi mungkin tidak bisa diakses. 
# Dari PC, saat HP ada di recovery
adb shell "rm -rf /data/adb"

7.5 Flash ZIP

  • Pilih Install → cari Zenith-Rosemary-ksun-*.zip
  • Swipe to confirm flash
  • Tunggu sampai selesai

7.6 Reboot System

Pilih Reboot → System di recovery. Boot pertama bisa lebih lama dari biasanya, jadi tunggu sekitar 5 menit sebelum memutuskan ada masalah.

7.7 Install KernelSU Next Manager

  • Download APK dari repo resmi KernelSU Next
  • Install di HP
  • Buka dan cek status

7.8 Verifikasi Root

adb shell su -c id

Harus muncul uid=0(root). Kalau ditolak, buka aplikasi manager dan izinkan akses root untuk Shell.

★Build Non-KSU

Kernel tanpa KernelSU. Hook manual di 5 file tidak perlu dilepas: semuanya dibungkus #ifdef CONFIG_KSU, jadi tidak ikut ter-compile saat CONFIG_KSU mati. KernelSU dimatikan lewat .config di folder output, jadi defconfig di repo tidak disentuh dan build KSU tetap bisa diulang kapan saja.

Cek Defconfig

cd ~/android/android_kernel_xiaomi_rosemary
git diff arch/arm64/configs/rosemary_defconfig

Kalau ada perubahan dari langkah 4 dan kamu ingin hasil yang persis stock (termasuk CONFIG_KPROBES bawaan), batalkan perubahan yang belum di-commit:

git checkout -- arch/arm64/configs/rosemary_defconfig

Build

export PATH="$HOME/toolchain/proton-clang/bin:$PATH"
export LD_LIBRARY_PATH="$HOME/toolchain/proton-clang/lib:$LD_LIBRARY_PATH"
export ARCH=arm64
export SUBARCH=arm64
export CROSS_COMPILE="$HOME/toolchain/proton-clang/aarch64-linux-gnu/bin/aarch64-linux-gnu-"
export CROSS_COMPILE_ARM32="$HOME/toolchain/proton-clang/arm-linux-gnueabi/bin/arm-linux-gnueabi-"
export LLVM=1
export LLVM_IAS=1

rm -rf out-nonksu
make O=out-nonksu ARCH=arm64 CC=clang HOSTCC=clang HOSTCXX=clang++ rosemary_defconfig

# Matikan KSU di .config, lalu rapikan dependensinya
scripts/config --file out-nonksu/.config -d KSU
make O=out-nonksu ARCH=arm64 CC=clang HOSTCC=clang HOSTCXX=clang++ olddefconfig

# Harus tidak ada CONFIG_KSU=y
grep -i ksu out-nonksu/.config

make O=out-nonksu -j$(nproc) \
    ARCH=arm64 \
    CC=clang \
    HOSTCC=clang \
    HOSTCXX=clang++ \
    2>&1 | tee build_nonksu.log

Packing Non-KSU

cp out-nonksu/arch/arm64/boot/Image.gz-dtb ~/android/AnyKernel3-KSU/
cd ~/android/AnyKernel3-KSU
DATE=$(date +%Y%m%d)
zip -r9 "Zenith-Rosemary-non-${DATE}.zip" * -x "*.zip"

Hasil: Zenith-Rosemary-non-YYYYMMDD.zip

§Cheat Sheet

Langkah 1–4 (cleanup, setup KernelSU Next, patch hook, defconfig) cukup dilakukan sekali. Setelah itu build, verifikasi config, dan packing bisa dijalankan dengan satu script. Unduh build.sh

#!/usr/bin/env bash
# build.sh - build + packing kernel Rosemary (KernelSU Next / Non-KSU)
# Pakai : ./build.sh ksu     -> kernel dengan KernelSU Next (manual hook)
#         ./build.sh nonksu  -> kernel tanpa KernelSU
# Path bisa diganti lewat environment, contoh: TC=$HOME/clang ./build.sh ksu
set -euo pipefail

MODE="${1:-}"
KERNEL_DIR="${KERNEL_DIR:-$HOME/android/android_kernel_xiaomi_rosemary}"
TC="${TC:-$HOME/toolchain/proton-clang}"
AK_DIR="${AK_DIR:-$HOME/android/AnyKernel3-KSU}"
DEFCONFIG="${DEFCONFIG:-rosemary_defconfig}"

case "$MODE" in
  ksu)    OUT=out-ksun;   TAG=ksun ;;
  nonksu) OUT=out-nonksu; TAG=non  ;;
  *) echo "Pakai: $0 ksu|nonksu" >&2; exit 1 ;;
esac

[ -x "$TC/bin/clang" ] || { echo "Clang tidak ditemukan di $TC/bin" >&2; exit 1; }
[ -d "$AK_DIR" ]       || { echo "Folder AnyKernel tidak ada: $AK_DIR" >&2; exit 1; }

# Environment harus siap SEBELUM generate .config
export PATH="$TC/bin:$PATH"
export LD_LIBRARY_PATH="$TC/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export ARCH=arm64 SUBARCH=arm64
export CROSS_COMPILE="$TC/aarch64-linux-gnu/bin/aarch64-linux-gnu-"
export CROSS_COMPILE_ARM32="$TC/arm-linux-gnueabi/bin/arm-linux-gnueabi-"
export LLVM=1 LLVM_IAS=1

MAKE_ARGS=(O="$OUT" ARCH=arm64 CC=clang HOSTCC=clang HOSTCXX=clang++)

cd "$KERNEL_DIR"
touch .scmversion
rm -rf "$OUT"

echo ">> [$MODE] generate .config"
make "${MAKE_ARGS[@]}" "$DEFCONFIG"

if [ "$MODE" = nonksu ]; then
  # Matikan KSU lewat .config, defconfig di repo tidak disentuh
  scripts/config --file "$OUT/.config" -d KSU
  make "${MAKE_ARGS[@]}" olddefconfig
  if grep -q '^CONFIG_KSU=y' "$OUT/.config"; then
    echo "CONFIG_KSU masih aktif, batal." >&2
    exit 1
  fi
else
  if ! grep -q '^CONFIG_KSU=y' "$OUT/.config"; then
    echo "CONFIG_KSU tidak aktif di .config, cek langkah 2-4 di dokumentasi." >&2
    exit 1
  fi
  if grep -q '^CONFIG_KPROBES=y' "$OUT/.config"; then
    echo "PERINGATAN: CONFIG_KPROBES aktif, padahal manual hook seharusnya tanpa KPROBES." >&2
  fi
fi

echo ">> [$MODE] compile"
make "${MAKE_ARGS[@]}" -j"$(nproc)" 2>&1 | tee "build_${TAG}.log"

IMG="$OUT/arch/arm64/boot/Image.gz-dtb"
[ -f "$IMG" ] || { echo "Build gagal: $IMG tidak ada. Cek build_${TAG}.log" >&2; exit 1; }

echo ">> [$MODE] packing"
cp "$IMG" "$AK_DIR/"
ZIP="Zenith-Rosemary-${TAG}-$(date +%Y%m%d).zip"
cd "$AK_DIR"
rm -f "$ZIP"
zip -r9 "$ZIP" * -x "*.zip"
echo ">> Selesai: $AK_DIR/$ZIP"

Cara pakai:

chmod +x build.sh
./build.sh ksu       # kernel + KernelSU Next
./build.sh nonksu    # kernel tanpa KernelSU

Script berhenti dengan pesan jelas kalau toolchain atau folder AnyKernel tidak ada, kalau CONFIG_KSU tidak aktif di mode ksu, atau kalau Image.gz-dtb tidak terbentuk.
